# Scalp Strategy Spec — `scalp_v1`

**Product**: `crypto-chatbot` (personal use, Gate USDT-settled perpetuals, manual execution from Telegram alerts)
**Status**: Draft v1 — replaces the swing MTF alert flow as the active strategy
**Applies on top of**: PRD v1.7 (all invariants stay: closed candles only, point-in-time data, LLM narrates only, trial registry, parameter freeze, parity tags)

---

## 0. Decisions & Scope

| Decision | Choice |
|---|---|
| Active strategy | `scalp_v1` (config `strategy: scalp_v1`) |
| Swing MTF flow (`4h/1h → 15m → 5m`) | Kept in code, **disabled** by config. Not deleted. |
| Execution | Manual, by the owner, from Telegram alerts. **Limit orders at a zone**, never "chase market". |
| Holding time | Minutes to max 90 minutes |
| Forward clock | Starts at the `scalp_v1` parameter freeze. Swing ledger rows are kept but reported separately (`strategy` column). |
| Rollout | Backtest → shadow forward (2–4 weeks, alerts tagged `[SHADOW]`) → live alerts |

**Honest constraint**: scalping with manual execution and retail fees is the hardest setting to have a real edge. Costs and human latency eat most of the gross edge. This spec is built so the data will tell you clearly — and early — if there is no edge.

---

## 1. Universe

Only the deepest markets. Spread and depth matter more than "interesting" price action.

- **Initial list**: BTC, ETH, SOL, XRP, DOGE.
- **Eligibility rules** (evaluated weekly, point-in-time snapshot stored):
  - 24h quote volume on Gate ≥ `min_vol_24h_usd` (initial: 100M)
  - median spread over the last 7 days ≤ `max_spread_bps` (initial: 1.0)
  - median L2 depth within ±10 bps ≥ `min_depth_usd` (initial: 250k each side)
  - listing age ≥ 180 days; not TradFi, not stablecoin
- `config/universe_scalp.txt` is generated by `crypto-chatbot universe refresh --strategy scalp_v1` and committed.

## 2. Timeframes & Cadence

| Role | Timeframe | Purpose |
|---|---|---|
| Context | 1h (4h levels only, never a gate) | Selects the **mode** (trend pullback / range fade / no trade) |
| Setup | 15m structure + 5m zone | Zone, invalidation (SL), targets |
| Trigger | 5m closed candle | Confirms entry; 1m used **only** in backtest/settlement to sequence intrabar events |

- **Cadence**: `alerts run` every 5 minutes, 20 seconds after the 5m close (`*:00/5:20 UTC`).
- `run_id = "scalp:<5m close_time>"`. Idempotent. Advisory lock unchanged.
- Settlement: every 1 minute using 1m candles (`settle-setups --strategy scalp_v1`).

---

## 3. Mode Selection (1h context)

Computed from the last **closed** 1h candle, using the shared analysis function (parity-tested).

| Mode | Condition (initial values) |
|---|---|
| `TREND_PULLBACK_LONG` | 1h regime `TRENDING_UP` (ADX ≥ 25, +DI > −DI, close > EMA50) **and** 15m structure not bearish |
| `TREND_PULLBACK_SHORT` | mirror |
| `RANGE_FADE` | 1h regime `RANGING` (ADX < 20) **and** a valid range exists (§4.2) |
| `NO_TRADE` | `HIGH_VOLATILITY`, `TRANSITIONAL`, any blocking filter in §6, or data quality ≠ READY |

The mode and its inputs are stored with every decision (also when `NO_TRADE`).

## 4. Setups

### 4.1 Trend Pullback
- **Zone** (first match): active 15m FVG or OB in trend direction within 1.5 × ATR(5m); else EMA20(15m) ± 0.15 × ATR(15m).
- **Trigger** (5m closed candle, after price touched the zone): 5m CHoCH/BOS in trend direction, **or** rejection candle (close back outside the zone in trend direction, body ≥ 0.5 × ATR(5m)).
- **SL**: beyond the 5m swing that formed inside the zone, + 0.25 × ATR(5m) buffer.
- **TP1**: 1.0R (close 60%, SL → break-even + costs). **TP2**: min(nearest opposing 15m swing, 2.0R) (close remaining 40%).
- **Time stop**: close at market if neither TP1 nor SL within `max_hold_bars_5m` (initial: 18 = 90 min).

### 4.2 Range Fade
- **Valid range**: 1h/15m dealing range from the last two confirmed swings; width ≥ 6 × expected round-trip cost **and** ≥ 1.5 × ATR(1h).
- **Trigger**: liquidity sweep of the range edge on 5m (wick beyond, **close back inside**) = failed breakout.
- **SL**: beyond the sweep extreme + 0.25 × ATR(5m).
- **TP1**: range midpoint (60%). **TP2**: 80% of the way to the opposite edge, capped at 2.0R (40%).
- Same time stop as 4.1.

### 4.3 Common Rules
- Min risk distance: `R_bps ≥ min_r_bps` (initial: 20 bps) — avoids stops inside noise.
- Max risk distance: `R_bps ≤ max_r_bps` (initial: 80 bps).
- Cost gate (§5): total expected cost ≤ 15% of 1R.
- Net R:R to TP2 after costs ≥ 1.3.
- **Entry validity**: limit order valid for `entry_valid_bars_5m` (initial: 3 bars = 15 min). Cancelled if TP1 is touched before fill.

## 5. Execution & Cost Model (per symbol, per order type)

| Component | Source |
|---|---|
| Fees | Config by VIP tier and order type. Gate VIP0 futures: maker 0.02%, taker 0.05%. |
| Spread | Half-spread from the L2 snapshot at signal time (fallback: 7-day rolling median, flag `SPREAD_ESTIMATED`) |
| Slippage | From L2 depth for `order_notional_usd` (config), taker legs only (fallback flagged) |
| Funding | Signed historical/current funding if a settlement falls inside the holding window |

- **Order types**: entry = maker limit; TP = maker limit; SL and time stop = taker.
- Expected cost per trade is shown in the alert in bps and as % of 1R.

## 6. Filters (blocking → `NO_TRADE`)

| Filter | Rule (initial) | Reason |
|---|---|---|
| Funding window | ±10 min around 00:00, 08:00, 16:00 UTC | Spikes, funding-driven flow |
| Scheduled macro events | Windows from `config/event_calendar.yaml` (manual list: CPI, FOMC, NFP…), −15/+30 min | Gap risk |
| Liquidation cascade | Gate `contract_stats` long or short liq (5m) ≥ P99 of 30-day history → block 3 bars | Disorderly market |
| Crowded funding | \|funding 8h\| ≥ 0.05% → block entries in the crowded direction | Squeeze risk |
| News burst | ≥ N articles mentioning the symbol in the last 30 min (N from 30-day P99) | Event risk |
| Daily stop | Realized ≤ −3R today (UTC) on taken trades → no more alerts today | Protects the trader |
| Loss cooldown | After an SL on a symbol → that symbol blocked 30 min | Revenge-trade prevention |
| Max concurrency | ≥ 2 open taken trades → no new alerts | Correlation risk |

## 7. Sentiment & Flow — How They Are Used

Rule: in v1 **nothing in this section is a trigger**. It is either a blocking filter (§6) or a recorded feature. Directional use only after the data proves it (§9.5).

| Signal | Source | v1 use |
|---|---|---|
| Taker buy/sell ratio (5m, last 3 bars) | `contract_stats` long/short taker size | Recorded feature; soft filter candidate |
| CVD ratio 15m | taker sizes | Recorded feature |
| OI change 1h vs price change 1h | `contract_stats` | Recorded feature (buildup / flush label) |
| Top-trader L/S | `contract_stats` | Recorded feature |
| Funding 8h | funding table | Filter (crowded) + feature |
| Liquidations 5m | `contract_stats` | Filter (cascade) + feature |
| News count / tone 30m | `sync-news` | Filter (burst) + feature; tone never directional |
| Fear & Greed | daily | Context feature only |

All features are stored **at decision time** (point-in-time) on every decision row, including `NO_TRADE` and `WAIT` — this is the dataset for later research and ML.

- `[SHADOW]` tag during the shadow phase.

## 9. Backtest (laptop)

### 9.1 Data
- Gate bulk (`download.gatedata.org`, `futures_usdt`): 1m candlesticks (or build from trades), mark prices, `funding_applies`, ≥ 12 months.
- `contract_stats` backfill (≤ ~179 days available) → flow features only for that window.
- L2 history is **not** available → spread/slippage in backtest use per-symbol conservative estimates from recorded live L2 (median + P90 variant).

### 9.2 Engine (event-driven, 1m resolution)
- Signals generated on 5m closes exactly as live (shared code path, parity test).
- **Human latency**: limit order placed `human_delay_sec` after the alert (initial: 90 s). If price is already beyond the zone, the order rests; if TP1 touched before fill → cancelled.
- **Maker fill rule**: filled only if a later 1m bar trades **through** the limit by ≥ 1 tick (touch is not enough).
- Intrabar order on each 1m bar: SL before TP (conservative). Gap through SL fills at open.
- Costs per §5, funding signed, time stop at market (taker).

### 9.3 Validation protocol (pre-registered)
- Parameters in §3–§6 are **fixed before** running the backtest; any change is a new registered trial.
- Final 3 months = untouched holdout; walk-forward on the rest with monthly folds.
- Report per mode, per symbol, per hour-of-day (UTC), per weekday.
- Required stats: trades, fill rate, win rate, expectancy (R) with **block-bootstrap 95% CI (by day)**, profit factor, max DD (R), cost sensitivity at 1.0 / 1.5 / 2.0×, break-even cost multiplier, DSR with registered trial count.
- **Random-entry benchmark**: same symbols, same time distribution, same SL/TP distances and costs, random direction/entry → the strategy must beat it, not just zero.
- Acceptance for going to shadow: holdout expectancy > 0 at 1.0× **and** ≥ 0 at 1.5× costs, ≥ 300 filled trades per active mode, beats random-entry benchmark (CI of the difference > 0).

### 9.4 What kills the strategy (decide in advance)
- Fill rate < 40% (zones are never reached) → zone logic wrong.
- Gross edge > 0 but net ≤ 0 at 1.0× costs → no tradable edge; stop.
- Edge only in one symbol or one month → not robust; stop or narrow scope deliberately (new trial).

### 9.5 Sentiment/flow research (after ≥ 4 weeks of forward features)
- Univariate: outcome R by bucket of each §7 feature (quintiles), with CI.
- Only features with a stable, monotonic effect in both backtest window (where available) and forward data may become filters in `scalp_v2` (new freeze).

|---|---|---|---|
